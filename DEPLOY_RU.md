# Обновлённый SEO-бот

## Что изменено

- Публикация привязана к трём слотам по Москве: 09:00, 15:00 и 21:00.
- GitHub Actions проверяет расписание каждые 15 минут. Если слот ещё не записан как опубликованный, запуск повторяется; после короткого сбоя бот догоняет публикацию.
- В `links.txt` сохраняется ID слота, чтобы повторная проверка не создавала второй пост для уже закрытого слота.
- Счётчик разделов меняется только после публикации. Ошибки генерации, загрузки и Telegraph теперь завершают задачу ошибкой, а не маскируются зелёным статусом.
- В день публикуется не более трёх постов. При многодневном отключении GitHub Actions может накопиться очередь: одновременное соблюдение лимита в 3 поста и догон всех пропущенных слотов за один день невозможно.

## Установка

Скопируйте содержимое папки `seo-post-main` в корень GitHub-репозитория, сохранив текущие `counter.txt` и `links.txt`. Затем отправьте изменения в default branch: расписание GitHub запускает workflow именно из default branch.

В репозитории должны оставаться секреты `OPENROUTER_KEY` и `IMGBB_KEY`. В **Settings → Actions → General → Workflow permissions** включите разрешение записи в репозиторий, иначе workflow не сможет сохранить опубликованные ссылки и счётчик.

В Actions будут появляться проверки каждые 15 минут, но публикации выполняются только по трём слотам. Время фактического запуска может немного сдвигаться. GitHub Actions использует best-effort планировщик, поэтому абсолютную гарантию без пропусков дать нельзя; повторные проверки снижают риск и автоматически повторяют временные сбои.
